# Operations

Running, upgrading and watching SARPEBE. For first-time setup see [getting-started.md](getting-started.md); for every variable see [configuration.md](configuration.md).

## Processes

| Process | Command (from `sarpebe-backend/` unless noted) | Notes |
|---|---|---|
| API | `uvicorn app.main:app --port 8000` (add `--reload` in development; use several workers in production) | Stateless. Disposes its DB engine on shutdown. |
| Worker | `celery -A app.tasks.celery_app worker --loglevel=info` | Runs ingestion and generation. Prefetch 1, late acknowledgement, so a crashed worker's task is redelivered. On Windows use `--pool=solo`. |
| Frontend | `pnpm build` then `pnpm start` (from `sarpebe-frontend/`) | Needs `NEXT_PUBLIC_API_BASE_URL`, `NEXTAUTH_URL`, `NEXTAUTH_SECRET` at build and run time. |
| Redis | external | Broker, result backend (results expire after 1 hour), rate-limit counters. |

Scale the worker for throughput: each generation is mostly waiting on the model, so several worker processes or higher concurrency help. Job status never depends on Celery results, only on the `lesson_plans` row.

## Database

- Use the Supabase **transaction pooler** (port 6543) in production, with the asyncpg URL (`postgresql+asyncpg://`). The API engine uses `pool_size=5`, `max_overflow=10`; keep the sum under the pooler's client limit across all API workers. Celery tasks create their own `NullPool` engine per task run (`task_session_scope`), because each task starts a fresh event loop.
- Required extension: `vector`. Check the version with `SELECT extversion FROM pg_extension WHERE extname='vector';` (0.8 or newer enables `hnsw.iterative_scan`; older versions work but filtered searches may return fewer rows).
- Take backups through Supabase. Chunks and embeddings can be rebuilt from the stored PDFs with `scripts.reindex_documents`; users, plans and cost logs cannot.

### Migrations

```bash
alembic upgrade head          # apply
alembic current               # show the applied revision
alembic downgrade -1          # undo the last one (check the downgrade first)
alembic revision --autogenerate -m "describe the change"   # new migration; always read the generated file
```

Rules: review autogenerated output, keep migrations reversible, never edit one that has been applied elsewhere, and do not run `upgrade` against a shared database without agreeing on it first. After a deploy that includes `c4d8e1f2a903` and `d5e9f3a4b017`, run `python -m scripts.reindex_documents --all`. The revision list is in [database.md](database.md).

## Reindexing documents

An admin can also process one document again from the curriculum page ("Proses ulang"), which queues the same task as an upload. Use the script for many documents at once.

```bash
python -m scripts.reindex_documents                # only documents still on an older ingest_version
python -m scripts.reindex_documents --all
python -m scripts.reindex_documents --id <document uuid>
```

Downloads each PDF from Storage and rebuilds its chunks with the current pipeline (table-aware extraction, structure-aware chunks, normalized embeddings, metadata). It calls the embedding model, so it costs tokens. Do it after changing `GEMINI_EMBEDDING_MODEL`, the chunking rules, or after upgrading from ingestion v1 (`ingest_version = 1`). Do not mix embeddings from different models; the model name is stored per chunk for that reason.

## Accounts

```bash
python -m scripts.seed_users                              # admin and teacher from SEED_* variables
python -m scripts.create_user <email> <password> [--role admin] [--name "Full Name"]
python -m scripts.upgrade_user <user_id> [role]           # role defaults to admin
```

`create_user` creates or updates a verified account. These scripts write to the database configured in `.env`.

## Cost and usage monitoring

- Every model call writes `llm_cost_logs`. Per user: `GET /api/users/me/costs`. All users (admin): `GET /api/users/costs`.
- Group by operation to see where money goes:

```sql
SELECT operation_type, count(*) AS calls, sum(prompt_tokens) AS prompt, sum(completion_tokens) AS completion, sum(total_cost) AS cost
FROM llm_cost_logs GROUP BY operation_type ORDER BY cost DESC;
```

- Pricing lives in `app/utils/cost_calculator.py`; update it when model prices change.
- Quality and cost levers: `GENERATION_THINKING_LEVEL`, `GENERATION_MAX_OUTPUT_TOKENS`, `RAG_USE_RERANK`, `RAG_TOP_K`.

## Logs and what to look for

- API: uvicorn access log plus application logs. Worker: Celery log; generation logs `Retrieved N passages`, `Generation completed`, and `Generation stopped: <reason>` for permanent failures.
- `Retrieved 0 chunks` or "belum membahas topik ini" means no document matches the labels or the topic; see [troubleshooting.md](troubleshooting.md).
- Rate-limit warnings (`Rate limit read failed`) mean Redis is unreachable and login throttling is off.
- A failed document stores its reason (Indonesian text) as the single entry of `curriculum_documents.ingest_warnings`; for completed documents that column lists page warnings (for example pages without text).

## Deployment checklist

1. `.env` complete; `EMAIL_BACKEND=smtp` with working SMTP; real `FRONTEND_URL`; strong `AUTH_JWT_SECRET` and `NEXTAUTH_SECRET`; `CORS_ORIGINS` set to the real origin.
2. Database through the pooler; `vector` extension enabled; `alembic upgrade head` applied; Storage bucket `sarpebe-storage` exists and is public.
3. Redis reachable from both API and worker (same `REDIS_URL`).
4. Worker running; one real generation tested end to end.
5. At least one admin account exists; curriculum documents uploaded with labels teachers will use.
6. `RAG_MIN_SIMILARITY` calibrated with the retrieval evaluation ([ai-evaluation.md](ai-evaluation.md)).
7. HTTPS in front of both apps. The SSE stream sets `X-Accel-Buffering: no`; make sure a proxy does not buffer it, or the UI falls back to polling.

## Routine tasks

| Task | How |
|---|---|
| Add curriculum | Admin uploads PDFs in the app; labels must match what teachers type. |
| Replace a document | Delete it and upload the new one (chunks are removed with it). |
| Change a prompt | Edit, bump `PROMPT_VERSION`, run tests and evals ([ai-pipeline.md](ai-pipeline.md)). |
| Rotate `AUTH_JWT_SECRET` | Change it and restart the API; all access tokens become invalid and clients refresh. |
| Investigate a failed plan | Read `generated_content->>'error'` and `generation_meta` on its `lesson_plans` row, and the worker log for its id. |
